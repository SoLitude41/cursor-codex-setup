# LinkedIn Organic Content Strategy for B2B SaaS

## Objective

Research how experienced B2B SaaS marketers and creators use organic LinkedIn content, then organize source material that can support a future playbook.

## Why These Experts

All 10 experts were chosen because they actively practice organic content and distribution themselves, not just write about it in the abstract, and because together they cover the range of skills a B2B SaaS content playbook needs: solo creator systems and audience building (Justin Welsh), founder-led B2B brand and community building (Dave Gerhardt), demand generation and B2B thought leadership (Chris Walker), content distribution strategy (Ross Simmonds), zero-click and audience-research-driven content (Amanda Natividad), product positioning and messaging (April Dunford), evidence-led marketing and conversion research (Peep Laja), research-backed product/growth writing at scale (Lenny Rachitsky), SaaS growth and pricing analysis (Kyle Poyar), and SEO-led organic growth for B2B SaaS (Gaetano Nino DiNardi). Full annotations for each expert are in `research/sources.md`.

## What Has Been Collected

| Source type | Status | Method |
|---|---|---|
| LinkedIn posts (10 experts, 1 post each) | Collected | Post text manually pasted by the project owner, verbatim, into `research/linkedin-posts/[author]/post-01.md` |
| YouTube transcripts (10 experts, 1 video each) | Collected | Video metadata (title, channel, publish date) and full transcript text fetched programmatically via the [Supadata](https://supadata.ai) API, using `scripts/collect-youtube-transcripts.ps1` |
| Supplementary sources (10 experts, 1 each) | Collected | One additional newsletter, blog, or podcast piece per expert in `research/other/`, with title/URL/date verified and summarized from the live page |
| Expert index with links, dates, annotations | Collected | `research/sources.md` |

Nothing in this repository is fabricated. LinkedIn post text is exactly what the project owner supplied. YouTube transcripts and metadata are the unmodified output of the Supadata API (only double HTML-entity-encoded punctuation was decoded). `research/other/` summaries are generated by fetching and reading the live source page, not from memory.

**Known limitation:** each expert currently has one LinkedIn post, one YouTube transcript, and one supplementary source. This is enough to establish sourcing and prove the collection pipeline works end-to-end, but a real playbook would need a larger sample (several posts/videos per expert) to identify repeatable patterns rather than one-off examples.

## Repository Structure

```text

├── sources.md              # expert index: links, dates, annotations, collection status
├── linkedin-posts/
│   ├── index.md
│   └── [author]/post-01.md # manually collected post text
├── youtube-transcripts/
│   ├── index.md
│   └── [expert]-video-01.md # Supadata API metadata + transcript
└── other/
    ├── index.md
    └── [expert].md          # one supplementary source per expert

scripts/
├── video-manifest.json               # expert -> YouTube video ID mapping
└── collect-youtube-transcripts.ps1   # Supadata API collection script
```

## Methodology

1. Select experts who actively practice B2B SaaS content, growth, positioning, demand generation, or audience-building work themselves.
2. Use LinkedIn profiles as identity anchors; manually collect one representative post per expert into `research/linkedin-posts/`.
3. Collect YouTube video metadata and full transcripts programmatically via the Supadata API (`scripts/collect-youtube-transcripts.ps1`, reading `scripts/video-manifest.json`). The API key is passed via the `SUPADATA_API_KEY` environment variable at runtime and is never committed.
4. Collect one additional supplementary source per expert (newsletter, blog, or podcast) into `research/other/`, verified by fetching the live page rather than relying on memory.
5. Record collection dates, source URLs, and selection annotations in Markdown files.
6. Commit and push in logical increments as each source type is completed, rather than in one final commit.
